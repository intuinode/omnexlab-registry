Use a free subdomain with GitHub Pages

About 5 minutes · works with any GitHub Pages site

This guide shows how to use a free yourname.omnexlab.site address as the custom domain of your GitHub Pages site. omnexlab.site only provides the DNS name; your site stays on GitHub Pages.

Do the GitHub Pages step first. Set the custom domain in your repository before you request the name. Until GitHub Pages has it, someone else could claim the name, so the request is refused.

What you need

  • A repository with GitHub Pages turned on.
  • A GitHub account at least 30 days old (one subdomain per account).
  • A free, allowed name: 3-32 letters, digits or hyphens. See the rules.

Step by step

  1. Set the custom domain. In your repository open Settings → Pages, type yourname.omnexlab.site into Custom domain and save. GitHub says the DNS check failed. That is expected for now.
  2. Note your Pages address. It is username.github.io, where username is your GitHub account name (for a project site the address is still username.github.io).
  3. Request the subdomain. On the home page enter your name and username.github.io, then press the button. GitHub opens a prefilled form; press Submit new issue.
  4. Wait for the bot. It checks that GitHub Pages has the name, creates the DNS record and replies All set, usually within a minute.
  5. Check Settings → Pages again. The DNS check can take a few minutes to turn green.

HTTPS

By default your name goes through Cloudflare, so visitors get HTTPS immediately, even before GitHub has issued its own certificate. GitHub's Enforce HTTPS option may stay unavailable for a while; that does not stop your site from working over HTTPS. If you choose Direct to my host, HTTPS comes from GitHub and can take a few minutes after the record exists.

Not for sensitive data. Do not use a free shared subdomain for logins, private data or payments.

Troubleshooting

  • "Your host does not have the name attached": set the custom domain in Settings → Pages (step 1), then submit the form again.
  • The DNS check keeps failing in GitHub: wait a few minutes. Because the name goes through Cloudflare, GitHub may keep saying the DNS is not exactly as it expects, even though the site works.
  • Your site shows GitHub's "There isn't a GitHub Pages site here": the custom domain is not saved on the right repository. Check Settings → Pages.

Questions

Do I need a CNAME file in my repository?

If you publish from a branch, GitHub adds one when you save the custom domain. If you deploy with a GitHub Actions workflow, the Settings → Pages value is what counts.

Is it really free?

Yes, today. See Plans & sponsors for what may change.

How do I remove it?

Use the cancel form. Only the owner can cancel, and the record disappears within minutes.
